# Windows Apollo/Moonlight 媒体集成验证

日期：2026-11-15。双端只安装 ScreenFerry；安装包以当前工作区源码构建，未发布 GitHub Release。

## 实现范围

- Apollo v0.4.6 原生 NVENC；移植同版本 RTP/NV_VIDEO_PACKET、短帧头、多块 FEC 与跨帧批次 pacing。
- 直接编译 Moonlight common-c 的 `RtpVideoQueue.c` 和 `rs.c`；上游重排和恢复算法由运行时调用，不再只复制一个 FEC 文件。
- AES-256-GCM、分域 nonce、防重放、来源限制、TLS 密钥/端口协商、双向可达性探测和同步 TCP 回退。
- 丢失参考帧时等待 IDR；关键帧请求、接收排队反馈和 1–18Mbps 码率调整已接入 NVENC/系统编码。
- 普通键鼠/UAC、原有屏幕方案、托盘和快捷键继续走 ScreenFerry 现有运行时。音频为现有 WASAPI PCM 加密传输，未切换到 Opus。

## 自动故障注入

Windows 公共平台接口测试使用真实 WinSock/CNG 和 Moonlight 队列：

| 场景 | 判定 |
|---|---|
| 360000 字节、多块 FEC、每第 17 个包丢弃（约 5.9%）、乱序及重复包；测试中继使用 1MiB 接收缓冲与 12Mbps 发送预算以隔离非注入的内核丢包 | 重组字节与原文一致，且实际恢复分片数大于零 |
| 同一会话穿插视频/音频 | 两轨道完整独立交付 |
| 错误会话密钥 | 无帧交付，认证拒绝计数增加 |
| 正确密钥但密文被篡改 | 在进入 FEC 队列前拒绝，无帧交付 |
| 双向加密 UDP 探测/不可达端点 | 可达成功，不可达按期限失败 |
| 超过 4096 包边界后重放首包 | 旧密文不再计为有效接收，也不进入 FEC 队列 |

真实 TLS 常驻运行时测试覆盖两个扩展方向：UDP 探测失败仍通过 TCP 持续呈现；UDP 建立后丢弃所有后续媒体，1.5 秒后同步回退 TCP、请求 IDR、继续呈现与回传按键；取消后确认来源释放。增加独立发送线程回归：人为让每次 UDP send 阻塞 500ms，两个方向的输入分别约 14.99/6.34ms 到达输入工作线程；这些是本机测试时长，不是双机延迟。测试不对 UDP 使用替代加密实现：运行时故障数据报仅用于注入通道状态，原生加密/FEC 由上述 Windows 测试独立覆盖。

逻辑测试验证 Annex B 三/四字节起始码的 IDR 恢复门控，丢包后拒绝依赖帧，以及码率快速下降、稳定五秒上调和上下限。

日志：`target/tmp/realtime-native-transport.log`、`realtime-session-tests.log`、`realtime-workspace-tests.log`。

## 本机原生链路

暂停已安装后台后，串行运行全部十项 Windows 条件测试；完成后恢复原后台。测试包含真实虚拟屏创建/回收、崩溃回收、左右上下与主屏切换、换向、光标、硬件编解码和隐藏窗口输入压力，十项均通过。

新增十秒原生测试完整经过：

`虚拟屏采集 → Apollo NVENC → AES-GCM UDP → Moonlight RTP/FEC → Windows 硬解 → D3D11 呈现`

本次静态桌面测试提交呈现 847 帧，约 84.7fps；来源时间戳至本机呈现调用返回的中位数 7.42ms、P95 12.24ms。共接收 4197 包，认证错误/丢帧均为 0。测试中途把码率从 18Mbps 调整至 10Mbps 并请求关键帧，链路继续运行；结束后移除本次虚拟屏并恢复布局。日志：`target/tmp/realtime-native-pipeline.log`。

这些数字来自本机回环和测试画面，不包含真实热点、显示面板扫描和双机输入到显示延迟，不能作为“双机已达 100fps / 零延迟”的证明。

## 双机验收

两台均安装同一个安装包。先关闭声音，在原热点分别开启两个方向，测试动态窗口、长页面滚动与鼠标，反复换向和取消，最后持续运行至少 30 分钟。日志应出现 `udp=true` 的实时媒体协商完成记录；若探测失败会明确记录 `udp=false`，运行时断流会记录同步回退 TCP。保留两端日志，结合帧数、FEC、IDR 等待、码率和呈现排队判断实际链路。

本轮未远程部署主控端，也没有取得新安装包在两台真实电脑之间的持续测试数据，这一项仍需双端升级后验收。
