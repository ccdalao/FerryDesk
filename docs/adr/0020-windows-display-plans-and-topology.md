# 0020：Windows 副屏方案与统一显示布局

状态：已实现；用户确认按 Windows 主显示器选择主、副屏。

## 背景

固定把虚拟屏放在右侧，同时保留另一套键鼠布局，会使反向拓展时窗口与鼠标从相反方向跨屏。用户要求保存多套方案，选择来源电脑、实体屏、接收屏、主屏、位置和快捷键，并允许任一端发起。

## 决定

配置版本 8 新增本机的 `display_plans`，默认空，保留版本 7 的声音、三个快捷键及普通键鼠布局。方案以设备指纹绑定对端，以相对于本机的桌面来源保存方向，不依赖主控/被控角色。最多 16 个方案，各方案可选 Ctrl+Alt+Shift+数字，与已有快捷键统一检查冲突。屏幕以 Windows DISPLAYn 的编号识别，失联或重新编号时明确要求重选。

新增 `DISPLAY_PLANS` 能力位。仅双方协商后发送屏幕清单和带参数的启动消息，保留旧启动消息及原线格式。未升级的设备继续普通共享和原有扩展操作；应用方案需要双方支持新能力。设备授权与独立媒体会话绑定不变。

Windows 启动时先激活虚拟显示目标，再以 CCD 的当前路径与模式表一次提交完整布局；主屏坐标为原点。该驱动的旧 GDI 暂存接口不能可靠完成涉及物理屏的主屏变更，因此仅用于最初激活虚拟目标。来源实体屏和接收的虚拟屏均可成为主屏，四个方向与来源实体屏贴合，位置被另一屏占用时报错。

进入拓展前把原主屏和实体屏坐标记录到当前用户 `HKCU\Software\ScreenFerry\DisplaySession` 的单个显示事务值。它是平台显示恢复状态，不是应用配置；不含设备授权或键鼠数据。正常退出和下次恢复通过 CCD 移除本程序虚拟路径并还原实体位置，成功后清除记录。接收窗口只使用选定的实体屏。既有启动与空闲清理继续有效。

主控显示对端桌面时，普通贴边入口临时取扩展位置的反方向，使用 `Live` 更新，不写回普通布局；主控扩展自己的桌面时继续暂停该设备的普通贴边入口。鼠标注入读取 Windows 当前虚拟目标坐标，不使用可能过期的 DXGI 坐标。DXGI 输出在切换期间不可枚举时使用已有备用路径并定期重试。

## 验证

公开平台接口测试覆盖两个主屏选择 × 四个方向的真实 Windows 坐标、光标所在显示器及取消恢复。子进程直接退出的测试覆盖虚拟屏作为主屏时的恢复。真实 TLS 集成测试从被控端保存并启动方案，确认首帧、参数传递、对应贴边入口及原设置保留。Flutter 操作测试覆盖新建、选择、保存及应用方案。

双机真实窗口拖动、多实体显示器热插拔、不同账户与长期连续切换仍需交互验收。
