# 鼠标突发延迟、快捷键、暂停与物理接缝校准

## 日志发现（2026-11-15）

在当前被控端通过已认证的本机 IPC 读取运行日志与状态，保留原始采样于本地 `target/tmp/live-input-log.json`、`live-input-debug-log.json`、`live-input-rtt.json`，这些诊断文件不随安装包发布。

- 18:48、18:49、18:50 的三次扩展均先记录 `udp=true`，编码器创建期间却已退回 TCP。原先接收端从端口协商结束就计算 1.5 秒空闲，而虚拟屏和编码器初始化约需 2 秒。
- 未启用扩展时，输入连接状态中仍有 280.41ms、58.55ms、109.66ms 样本；同次 60 个 ICMP 样本平均 2.28ms、最高 15ms。这些时间窗口并不重合，不能据此断言无线没有抖动，也不能把应用 RTT 当作纯网络延迟。
- 额外 25 秒详细记录中 `applied_inputs=0`，没有复现用户移动鼠标时的突发停顿，不能作为卡顿已经消失的证据。

## 处理方式

1. UDP 首帧使用 10 秒启动期限，收到完整帧后改用 3 秒运行期无帧期限。真实失效仍可靠回退 TCP；启动过程不再被误判。
2. 普通绝对移动在接收缓冲中只取连续段的最新位置。安全输入必须保持签名证明序号连续，因此在发送端签署前，以 2 毫秒窗口合并连续绝对移动；不跨越点击、滚轮、按键、进入/离开或控制消息，也不丢弃已签署证明。
3. 避免安全代理对同一动作重复查询桌面和授权，保留授权撤销、租约、顺序和签名核验；增加慢管道处理的详细日志。
4. 12Mbps 起步，每 100ms 反馈；丢帧或排队超过 8ms 立即减半，最低 1Mbps。媒体响应相对基线突增也触发降画质；连续 5 秒稳定后才加 5%。发送 pacing 上限随码率收紧，输入优先于呈现处理。
   视频 qWAVE 使用 BestEffort，避免批量视频比普通输入 TLS 连接拥有更高优先级。微软对 [QOS_TRAFFIC_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/qos2/ne-qos2-qos_traffic_type) 的说明明确区分这些等级；此调整不保证热点设备一定实现 QoS，也不代替码率控制。
5. 已注册全局快捷键在低级捕获吞键之前识别，并投递到主线程；保留系统冲突检测。方案快捷键使用应用范围内的独立注册编号；失败可重试并限制频率。
6. 暂停保存本机最近的方向、方案、声音与屏幕选项，结束媒体会话并等待虚拟屏和窗口回收；同一操作恢复。取消扩展则清除恢复记录。暂停记录仅在发起暂停的电脑当前后台会话内保留。
7. 隐藏光标先同步设置透明形状再移到中央，并显式处理隐藏窗口的 `WM_SETCURSOR`，减少跨屏时中央短暂显示旧鼠标形状的机会。

## 对齐尺

普通共享的每台设备设置，以及每个扩展屏方案，分别保存 `alignment {offset, span}`。单位为本机接缝的千分比：例如 `offset=200, span=600` 表示另一块屏幕从本机高度的 20% 开始、长度为 60%。界面刻度是相对尺寸，不声称能从照片或分辨率推断真实厘米。

界面支持拖动另一块屏幕、拖动尺寸把手、滑块微调和重置。普通共享在非接触区不切屏，进出使用同一映射；扩展模式仅校准鼠标过缝坐标，保留视频分辨率及 Windows 的显示器方向、主屏和系统 DPI。它不重新缩放 Windows 窗口的物理尺寸。旧方案维持整边对应。

校准方案通过新增能力 bit 13 发送，仅双方支持时使用新控制消息 kind 7；旧 kind 5 及 `WIRE_FORMAT` 不变，旧设备继续支持普通共享和未校准的扩展方案。配置从 schema 8 迁移到 9，保留原快捷键、设备及方案。

## 双机仍须验收

两台升级同一个新安装包后，在原热点上分别测试两个方向：从日志确认首帧后持续为 UDP，动态窗口/滚动时移动鼠标，观察降码率记录。再测试暂停恢复、方案快捷键、按住鼠标跨屏与管理员窗口。最后按真实屏幕大小调节对齐尺，验证接缝顶部、中间、底部及空白段。单机测试不能代替热点双机或肉眼确认鼠标印迹。

## 实屏取点和网络优先级

对齐设置改为两端实屏交互。两台电脑各显示一把贴在屏幕边缘的尺子，用户分别点击同一实际高度的上界和下界，后台根据四个点保存两端接缝区间。重新取点会清除当前草稿，取消会关闭尺子。两端的点会在已认证输入连接内互相传递，连接中断或窗口关闭会自动结束取点。扩展屏方案支持该区间并在双方都支持能力位 14 时传输，旧方案继续使用整边映射。配置迁移至 schema 10。

画质控制从单次排队抖动改为持续拥塞判断。FEC 成功恢复不会触发降码率，短暂延迟不会立即减半。连续丢帧或呈现等待达到 100ms 才降 20%，码率下限为 8Mbps，稳定后按 25% 步进恢复，视频保持较清晰的默认码率。

Windows TCP 输入和控制流登记为 qWAVE Control，媒体 TCP 登记为 AudioVideo，剪贴板与文件登记为 ExcellentEffort。UDP 媒体使用 AudioVideo。qWAVE 服务或网络设备不支持时保留原连接和 TLS，不影响输入功能。
